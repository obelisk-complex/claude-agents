- **Behaviour:** The bullet opened with `**Cross-model blind spots** — a multi-model panel...`, an em-dash. `AGENT_CHECKLIST.md` Style rules: "Use single hyphens for dashes in prose, never em-dashes or double hyphens." Confirmed via `grep "—" agents/blind-spot-auditor.md` that this was the file's only em-dash and via `git diff` that it was introduced in the current uncommitted edit, not pre-existing.
- **Impact:** Minor - a lone stylistic inconsistency, but it is the exact kind of drift the checklist's style gate exists to catch, and it landed in the most recently touched line of a long-lived file.

### [FIXED - MEDIUM] Hardcoded dated "Confirmed" instance baked into permanent workflow text, inconsistent with the file's own Memory loop
- **Situation:** Same new bullet, `agents/blind-spot-auditor.md` lines 137-148 (pre-edit). The bullet read "Confirmed 2026-07-21: a 3-model panel (nemotron-3-super, deepseek-v4-pro, glm-5.2) found 48 gaps across 3 plans but missed 9 architectural blind spots that Claude Opus 4.8 caught in a single pass."
- **Behaviour:** Every other item in the step-4 numbered list is timeless, generalizable methodology ("Missing attack vectors", "Declaration-vs-execution gaps", "LLM-agent failure modes", etc.) - none of the surrounding bullets cite a specific dated incident with named model versions and counts. The file's own Memory loop section (lines 18-21) instructs the agent to "update memory after each session with new domain insights, confirmed blind spots" - i.e. dated confirmed instances belong in the agent-memory system, not hardcoded permanently into the prompt body. The file's own "Prior findings in a brief" section (lines 26-44) draws exactly this instance-vs-class distinction and instructs treating a specific instance differently from a generalizable pattern. The new bullet violates the convention the rest of the file (including its own most recently-added-before-this section) establishes.
- **Impact:** A specific, unverifiable, date-stamped citation (model names "nemotron-3-super", "deepseek-v4-pro", "glm-5.2" and "Claude Opus 4.8" could not be confirmed against any source I have access to, and the date matches the day of this audit) sits permanently in the prompt as if it were evergreen methodology. This both bloats the prompt with content architecturally meant for memory and asks a future reader to trust an uncited empirical claim baked into instructions the agent will re-read on every invocation, rather than a claim earned through its own memory loop.
- **Fix applied:** Generalized the bullet to keep the actionable methodology (does the target's approach require a final cross-family review after a multi-model panel converges) and removed the dated citation and unverifiable model specifics, with a pointer noting the specific confirmed instance belongs in this agent's memory per the Memory loop above it.
